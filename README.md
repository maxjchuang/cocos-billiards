# Cocos 中式八球

Cocos Creator **3.8.7** + TypeScript。目标仅为移动端小程序/小游戏；所有玩法使用触屏，浏览器只用于开发预览。当前为**双人同屏、单局对战**，P1 固定先开球，无 AI 或联机。

## 设计文档

[产品与 UI / UX 设计方案 V1.9](docs/design/README.md)包含最新 PDF、S01–S17 SVG 图稿与线框图标。设计与当前实现的差异已在该目录列明，后续按设计逐步开发。

整体架构、功能差距、确认参数和实施阶段见[技术实现方案](docs/technical/implementation-plan.md)。

## 打开与启动

本机 Creator 位于 `/Applications/Cocos/Creator/3.8.7/CocosCreator.app`。打开本目录工程，等资源导入结束，在资源面板双击 `assets/scenes/Main.scene`，点击顶部 Play 进行浏览器预览。编辑时场景只有 `Billiards` 启动节点，球桌等对象在运行时生成。

电脑调试必须打开浏览器 DevTools 的手机设备与触摸模拟，再刷新。仅选择 Creator 预览栏的手机尺寸，不一定会启用触摸事件。游戏不提供键盘、桌面鼠标控制。

当前本机调试地址：<http://127.0.0.1:8766/>，服务仅绑定本机。该地址运行 Creator 导出的 Web Mobile 开发包，服务器停止后可在本目录运行 `npm run preview` 重新启动，**不是已发布的小游戏**。

## 触屏操作

1. 开局时在下方开球线后摆放白球，点击“确认摆球”。也可直接确认默认的合法白球位置。
2. 拖动底部力度条，范围 10%–100%，对应初速度 0.4–4 m/s。默认 60%，满力更适合开球；调整力度不击球。
3. 在球桌上按住并移动手指瞄准，松开击球。球杆位于母球后方，蓝色杆头指向球心。
4. 开球结束仍为开放球局；出杆前点击“进攻全色”或“进攻半色”。合法进指定组且首碰同组时，裁判确定双方球组。
5. 出现犯规后按裁判提示处理。自由球阶段可反复触摸球桌摆白球，位置不能重叠其他球、越界或落在袋口；确认后才能击球。线后自由球只能在开球线后摆放。
6. 严重开球违规时，非犯规方可选择自己重开、要求原开球方重开，或接受台面自由球。原开球方被要求重开后再次不足四球碰库，会被判负。
7. 界面显示当前球员、双方球组与剩余号码、犯规次数和最近判罚。胜负产生后停止出杆，可点击“再来一局”；“重新开局”始终会重置整局和判罚。

号码 1–7 是全色，9–15 是半色，8 是黑球，白球无号码。半色球使用程序生成的彩色环带与白色球面，号码使用随球位置同步的白底标牌，滚动时保持可读。无第三方图片、模型或远程运行库。

## 规则基线与裁判范围

固定采用中台协公开的 [《中式台球竞赛总则（2017 年 1 月修订）》](https://cbsa.cssf.net.cn/annoucement/2017/0120/142126.html) 第三章作为核心规则基线，**不是美式八球或球房自定义规则**。其中包括：

- 8 号置于球阵中心，底边两端分别为全色、半色，顶球置于置球点；本项目默认 P1 先开，不做比球。
- 开球有目标球进袋或至少四颗不同目标球碰库才合法。开球进球不分组；合法进球继续，合法无进球换人。
- 开放球局可先碰两组普通球，不能先碰 8。跨组传球进袋不能关闭开放球局。选组后，首碰必须为本组；清完本组才可先碰 8。
- 白球落袋、未碰目标球、首碰非法球、碰球后无进球且无球碰库，均自动判犯规并移交自由球。贴库球被推向原库不算有效碰库，必须离库后再回来，或由其他球满足条件。
- 普通犯规给对方全台自由球；开球普通犯规给线后自由球。线后球不得未越线就先击打仍在线后的目标球；所有合法目标都在线后时，会按距离重置最近的一颗到置球点。
- 合法打进本组球继续；仅进对方球换人但不因此单独判犯规；已经进袋的普通球不取回。
- 提前进 8、同杆清本组最后一球并进 8、进 8 同时犯规，判对手胜。清完本组后下一杆合法进 8 才获胜。打 8 时只白球落袋但 8 未进，不直接判负，给对方自由球。
- 开球进 8 不直接胜负：8 重置，合法开球者继续；进 8 伴随犯规，按规则提供接受台面或线后自由球选择（白球落袋时不能接受其原位）。
- 这一版规则**包括 8 号在内均无需指袋**，也没有普通“连续三次犯规自动输局”的规则。

裁判覆盖的是当前 XZ 平面仿真中可发生、可记录的事件。尚未模拟跳球/球出台、推杆/连击、身体触球、双脚离地、消极比赛警告、计时、比球、僵局处理或完整多局赛事。接近同时的碰撞按 240 Hz 求解器的事件顺序处理。击球时球未停稳、胜负已定、自由球未确认等操作会被界面直接阻止。**不能宣称已经完整复刻职业赛事裁判或真实袋口物理**。

## 代码地图

| 文件 | 职责 |
| --- | --- |
| `assets/scenes/Main.scene` | 最小场景，UUID 绑定启动脚本 |
| `assets/scripts/BilliardsGame.ts` | Cocos 场景、纹理与号码、触屏、HUD、裁判流程 |
| `assets/scripts/BilliardsPhysics.ts` | 纯 TypeScript 位置/速度、碰撞、库边和进袋事件 |
| `assets/scripts/BilliardsLayout.ts` | 独立布局计算：顶部状态、中央球桌视口、底部操作面板 |
| `assets/scripts/BilliardsRules.ts` | 独立裁判：球组、轮次、犯规、自由球、开球选择、胜负 |
| `tests/physics.test.cjs`、`tests/rules.test.cjs` | 物理、场景绑定和规则测试 |
| `scripts/preview.cjs` | 零依赖本机静态预览服务器，仅服务 Creator 构建产物 |
| `scripts/preview-smoke.js` | 手机触摸模拟下的实际引擎回归 |
| `HANDOFF.md` | 当前交接与验证边界 |

台面为 XZ 平面，Y 为高度，单位米/秒。物理固定 1/240 秒一步；卡顿或切后台最多保留 0.1 秒待模拟时间。画面滚动姿态不参与物理运算，不用于确定性联网。裁判监听首碰、逐次碰库和进袋事件，停稳后结算一次；母球不再自动复位，必须完成自由球摆放流程。纯物理 API 的旧自动复位选项仅留作兼容测试，游戏显式关闭它。

## 本地校验与构建

```sh
npm ci
npm run check
```

依赖仅用于官方 3.8.7 类型检查与 Node 测试，不包含 Creator 引擎服务器。不要用静态服务器直接打开源场景。新增文件保留各自 `.meta`，尤其不能改动已有启动脚本的 UUID。

在工程根目录构建浏览器开发包：

```sh
/Applications/Cocos/Creator/3.8.7/CocosCreator.app/Contents/MacOS/CocosCreator \
  --project "$PWD" \
  --build 'platform=web-mobile;debug=true;startScene=6193b456-902a-4a13-a5f8-3dedbf3cab39'
# Creator 成功退出码为 36，不是通常的 0。
npm run preview
```

若端口被旧服务器占用，请先停止旧服务器或换端口。Web Desktop 属于历史开发构建，不是当前产品支持目标。

启用手机触摸模拟并刷新后，在 Console 粘贴 `scripts/preview-smoke.js`，执行：

```js
previewSmoke().then(console.log).catch(console.error)
```

脚本先通过触屏走完弱开球、自由球与球组选择，随后布置小型确定性台面，通过真实触屏输入与引擎物理验证分组、黑八判负、合法黑八获胜及再开局。结束会重置球局。它是开发工具，不要在正在进行的对局中运行。
