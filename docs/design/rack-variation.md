# 开球变化方案：合法随机摆球与固定球体微差

2026-10-23；用户已确认的方向。版本mass-slot-v1。保持瞄准、力度、打点和220ms触球提交精准；本方案不增加出杆误差，也不改变球径或随机拉开球阵。

## 产品与UI/UX约束

每次新局和裁判要求重新摆球时，重新生成合法球号排列。顶球仍在置球点，黑8保持第三排中间，底排两端各为全色/半色，其它球号随机。沿用原有10微米数值间隔，不增加随机缝隙；白球默认位置和默认方向不变。依据[CBSA 2017规则](https://cbsa.cssf.net.cn/annoucement/2017/0120/142126.html)第三章。

不增加按钮、设置或技术信息。暂停、后台、设置、自由球摆放、接受现有台面均不重新抽球阵或质量。普通新局仍由玩家一先开。只有明确重新摆球才产生新rackSeed。

目标球具有很小的固定质量差异：归一化平均质量1，范围±0.5%；母球固定为1。差异按球号身份固定在同一球组上，重新摆球与刷新页面后保持；球号换到不同位置后，质量分布随球一起移动。若以165g理解，该范围约164.175–165.825g，仅为量级说明，并非厂家实测。质量范围是本项目仿真调优值，不宣称真实球组标定。

玩家设定的方向、力度、打点不加入随机偏移；母球初速度与旋转预算保持现有计算。变化由球体相撞后的物理响应产生，不保证进球或全部散开，不按比分、球组或散球结果筛选种子。

## 技术与复现

- `RackConfig`保存版本、rackSeed、ballSetSeed、massVariation。每次新局有新rackSeed；ballSetSeed代表同一球组，固定其个体属性。
- 求解身份bodyId按初始空间槽位固定，与球号id解耦，整个球局不变。计算顺序与输入数组排列无关。关闭质量微差后，只换号码必须得到相同的几何轨迹。
- 碰撞冲量及重叠修正按双方逆质量计算，维持动量与耗能约束。纯TS物理、球径、几何、旋转及裁判基线保留；仍不包含完整球间切向摩擦、跳球、飞台等现实模型。
- 随机配置只在初始化产生。物理步进、每次碰撞和出杆提交均不取随机数。
- 本机保存最近32份配方，键为eight-club.racks.v1。存储不可用或数据损坏时使用内存记录，游戏继续可用。记录不包含账号、昵称等个人信息，不上传远端。
- `createRack(config)`可重建球阵；开发预览可用`BilliardsGame.reset(config)`重放初始条件，不消耗正常的新局种子序列。裁判要求重摆时继续使用当前球组与质量幅度。
- 精确复现限定为同版本、同环境与相同输入；本轮不是完整回放产品或跨平台确定性联机认证。未来联机仍需权威状态和跨运行环境验证。

## 验收

1. 100个种子全部满足球号、黑8、顶球、尾角球组、无重叠与紧密摆放约束。
2. 相同配置和输入得到逐值相同的终态；质量在整个球局与重摆后不改变，母球出杆速度与旋转不随种子变化。
3. 均质控制组换50种球号排列，几何轨迹完全相同；数组倒序也不能改变结果。
4. 变化组使用同一球组的50个摆球种子，忽略球号、按1mm精度比较，产生50种几何终态；至少90%的两两对比存在2cm以上无编号位置集差异。所有局数值有限、在外框内且15秒内停稳。
5. 浏览器实际默认摆球、默认方向、100%触屏开球多次；新局变化、种子重放一致、记录恢复、暂停和裁判重摆正确。Creator引擎事件另验，真机与微信仍按用户要求豁免。

纯仿真对照及实际运行证据见validation/racks；过往固定球阵的力度和UIUX结果作为历史基线保留。
