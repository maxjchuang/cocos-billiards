## 2026-10-25：人机练习与三档难度

已增加离线人机练习，保留双人同屏。开局选择入门/标准/挑战并记住上次选择；暂停菜单可修改AI难度，从下一次思考生效，已锁定或运动中的杆保持原参数。AI覆盖开球、选组、自由球、违规开球处理、防守、基本走位与黑八结算，沿用现有物理/裁判和220ms触球提交。AI回合只允许暂停和查看资料，不允许人手代打。

设计见[AI方案](../design/ai-opponent.md)，实现见[AI技术方案](ai-opponent.md)，证据见[AI验证](../../validation/ai/README.md)。176项Node、Web Mobile构建、三个浏览器画幅和Creator原生专项通过；标准AI完整球阵31杆产生正常胜负。三档固定题库呈现整体能力差别，不代表通用胜率。真机/微信继续豁免。2026-10-25用户体验验证通过，批准提交并推送。

## 2026-10-24：A 方案音效接入

用户选择A写实球房方向。现已接入14段本地声音素材与13个独立通道，覆盖出杆、球球、碰库、进袋和合法获胜后的短掌声；没有裁判语音、环境底声、界面提示音或电子奖励音。轻重取自实际接触速度，开球按真实事件混音，保留旧碰撞尾音；暂停、后台、重开和静音清掉待播声音。掌声在合法获胜结算后延迟350ms播一次，犯规和普通进球不播。原220ms触球同步保留，物理轨迹逐值回归一致。

音效设计与边界见[音效A规范](../design/audio/README.md)，授权见[AUDIO-CREDITS.md](../../AUDIO-CREDITS.md)，游戏规则页内可查看音频署名。本轮验证见[音效验证](../../validation/audio-a/README.md)；2026-10-25用户已体验验证通过，批准提交并推送。

不为追求文件拆分改写裁判和物理。界面状态保留在现有协调组件中；纯设置与记录独立可测。全部新增资源保留meta，不改Main绑定UUID，不引入通用物理引擎、CDN或第三方美术。

资源与诊断：音频仅仓库内四个生成WAV，运行无远程加载；诊断事件有界，标签/按钮复用，50次菜单往返组件数稳定。开发脚本不进入游戏资源包。设置状态立即应用；减少动态与音效/振动均读取同一真实触球提交事件。

视觉基准为SVG与ui-contract.json；所有厂家未核验袋型字段继续为空，视觉与仿真使用明确标注近似的共享代理，不能当作实物精确尺寸。完整机器证据位于validation/ui-complete/acceptance.json；硬件触感/听感及真实后台仍不在本机自动化认证范围。

缩小的嵌入预览低于320 CSS宽时，以320逻辑宽度同比例呈现；HUD字体栅格采样和指针换算使用实际像素/逻辑单位比例，而非硬套设备DPR。标准手机画幅保持原像素规范。Creator GUI内81/35/28/9项触摸检查通过，100项Node测试通过；缓存恢复与调试器旧连接问题独立于游戏逻辑。

放大窗袋口避让补充：Game将共享袋口outline投影成HUD禁入矩形（12px余量），同时保护母球、接触点/目标与手指；纯函数placeMagnifier负责安全择位和位置保持，MagnifierView只负责同比例绘制、尺寸与生命周期。每次交互结束/区域变化重置择位；标准、112宽、96宽均无解时隐藏，不猜测目标袋、不改物理预测。运行回归检查实际Mask四角投影，避免只验证计算数据。实现细节与验收见design/magnifier-placement.md及validation/magnifier。

力度修订：内部UI强度0.4–4不再等于物理速度；在唯一触球提交中调用powerToSpeed，≤2.4保持原值，超过后为p + (8−4)×((p−2.4)/1.6)²。100%=8 m/s，物理strike独立钳制到8；默认60%及UI百分比/动效位移仍按原强度单位换算。外层固定240Hz，step内部按当前最大线速度、dt和0.6球半径的位移预算计算整数子步。它降低高速穿透风险，不引入通用物理引擎或宣称CCD。验收见design/shot-power.md与validation/power。

随机开球：BilliardsRack独立提供可验证RackConfig与PRNG，rackSeed决定合法号码排列、ballSetSeed决定目标球质量配置。Game从本机RackSession获取新配方，保存最近32份；开发重放可显式传配方且不消费正常序列。Referee通过纯rackFactory生成重摆，不依赖Cocos或自行调用全局随机。BallState新增只读bodyId/mass，数组仍按球号给UI使用；物理按固定空间身份排序，逆质量冲量与穿透修正。质量相同的换号控制必须得到完全相同几何轨迹，防止数值遍历顺序制造假随机。母球与输入保持不变。规范及验收见design/rack-variation.md和validation/racks。

## 1. 范围与约束

- 使用 Cocos Creator 3.8.7 + TypeScript，保留现有 Main 场景和启动脚本 UUID；新增资源保留各自 `.meta`。
- 面向移动端小游戏，只使用触摸；浏览器用于开发预览。
- 当前支持同屏双人及离线人机单局对战，保留头像、昵称和连接状态接口。AI已于2026-10-25获批实施；账号、匹配、联网服务器、排名及商业化仍不在本期。
- 球心在 XZ 平面运动，物理和裁判保持纯 TypeScript，不引入通用物理引擎。视觉的高度和阴影不改变球位。
- 裁判沿用中台协《中式台球竞赛总则（2017 年 1 月修订）》第三章，不增加指袋或普通三次犯规判负变体。现实身体犯规、跳球、飞台及完整赛事不在范围内。
- 核心规则、场景 UUID 和现有测试必须保留。提交前检查公开内容，排除机器绝对路径、私有镜像、内部服务地址、凭据与缓存。

## 5. 状态与输入

三组状态分别维护：

- 裁判阶段：`placing / ready / shooting / choice / over`，延用规则语义。
- 交互阶段：空闲、瞄准、调力度、微调、打点编辑、出杆准备。
- 覆盖层：无、暂停、设置、规则、重开确认、结算、完整玩家资料。

由对局控制派生 `canAim / canAdjustPower / canEditSpin / canShoot / canPlace`，UI 禁用和输入处理使用同一权限来源。打点弹层不推进仿真，打开时应已处于待击球阶段。暂停和切后台冻结仿真；恢复清掉时间积压，不能追算后台经过的时长。

每次触摸开始时确定归属：弹层 > 按钮 > 力度/微调 > 摆球/瞄准。归属直到结束或取消不变，跨区域不切换手势；只接受一根有效手指。弹层开关、失焦、暂停和重开清理触摸归属。

## 6. 出杆提交与同帧要求

点击时只做预校验，创建不可变快照：`shotId / gameId / player / direction / power / tipOffset / selectedGroup`。不调用 `beginShot`，不改变球速度；直到触球事件才原子提交裁判与物理。

- 时间线跨过触球点时先呈现触球状态，再推进该杆物理，不允许掉帧后直接跳到远离触球的图标状态。
- 使用唯一出杆编号和 `committed` 标志保证最多提交一次。提交前复核球局编号、裁判允许、球已停稳、参数有限值和方向合法；失败则取消，不留半提交裁判状态。
- 触球前暂停、切后台、离开或重开：取消准备，恢复需重新点击。
- 触球后暂停：保留已提交状态，恢复不补打、不回滚。进程被系统销毁后的跨进程恢复另行规划，不能承诺本机永久保存球局。
- 图标复位不恢复母球位置，也不表示可以立即再出杆。
- 音效与已开启振动由实际触球事件触发。减少动态仍使用同一触球事件。

## 7. 打点与旋转模型

面板打点采用相对球杆视角的左右/上下坐标；草稿限制在单位圆，中心吸附与设计 6 像素阈值对应。显示偏移百分比不表示转速。将沿杆坐标转换为桌面方向向量后，映射到初始角速度。

物理状态扩展三轴角速度和必要的静止/滑动/滚动状态；依次加入台呢摩擦、旋转衰减、碰球后的平移与旋转影响、侧塞碰库。不得用 UI 位移或额外固定推力伪装旋转效果。中杆样例先保持基本稳定，再用固定案例校准高低杆和侧塞。

停稳需要考虑仍可能驱动平移的角速度，并采用稳定门槛，不能因某一子步平移速度接近零就结算。单纯残余侧旋的截断策略需与模型一致，避免等待过长。母球摆放、重开和落袋清理对应旋转；裁判结算后只将下一杆打点回中，不清除本杆尚未结束的旋转。

测试案例：近距离正碰高杆跟进、低杆回拉、相同打点远距离衰减、相反侧塞碰同库的方向差异、组合打点、零打点、极限参数稳定性及最长停稳时间。固定参数和球位验证趋势，不在不同几何场景中承诺相同走位。

## 9. 身份、裁判与反馈

`PlayerProfile` 与规则座位分离，包含稳定 ID、昵称、头像来源和本地/设备视角角色；裁判仍按座位运算。长昵称按宽度省略，点击查看完整资料；空昵称使用“玩家一/玩家二”，头像失败使用同尺寸占位。身份位置固定，只切换回合强调。

普通提示 1.5–2 秒退出；需要摆球或选择时持续保留。开球选择纵向排列；结束层支持再开局和查看台面；查看台面不恢复操作。犯规累计移入规则页。

## 密集接触网络修订：network-v2

针对中央球堆滞留，BilliardsPhysics的solveBallContacts收集间距不超过球径+20微米且不正在分离的接触约束，按稳定bodyId顺序求解非负累积压缩冲量（最多100次，最大冲量变化小于1e-9时退出）。压缩阶段不执行逐对恢复；结束后按1+e统一恢复速度增量。有限迭代以质量加权的初始速度/增量内积限制恢复幅度，确保不增加原动能，冲量始终成对保持动量。位置投影独立执行3轮，不添加速度。双球解析恢复系数与原有cloth/spin/cushion预算保留。

全部普通击球使用同一求解器，无开球模式专属推力；容差覆盖原有10微米数值间距，不随机移位或扩大可视球径。首碰/后续碰撞事件仍传入独立Referee。版本与本机journal升级，旧配方拒绝，不能跨物理版本声称精确复现。验收指标与模型边界见design/rack-variation.md，运行证据见validation/core-spread。

## 本机候选：compliant-v3（真实性未验收）

network-v2整体压缩后统一恢复被用户体验否定。候选保存每个接触点的压缩变量q，按局部相对法向速度推进，正压缩时施加非负线性弹性/阻尼冲量；归一化步长0.01、时间上限16、静默20步退出。20微米邻接容差、0.0003间距时间尺度均为近似的数值设置，不是实测材料参数。单独两球保留解析恢复；多接触使用局部微步，末尾只做不增能限制而不整体乘1+e。法线固定、未包含球间切向摩擦及完整3D，仍需实拍标定。

新增半步长收敛、静止/分离接触、动量与不增能、方向和双角袋批量回归。测试中的分布/频率阈值仅针对固定输入的退化防护，不能当作真实球桌目标数据。131项检查、CLI与Web Mobile实际触摸通过；不等于真实开球验收，不自动推送候选。见validation/break-balance。

## 用户允许的摆球公差：rack-tolerance-v4

BilliardsRack.rackPositionOffsets使用独立种子流产生四排横向增量，累积偏移并用圆距计算纵向补偿。若原间距d，当前排相对上排错位delta，纵距取sqrt(d²-(d/2-|delta|)²)。排内距离d不变、最近父球距离d，无重叠，最多四步后偏移仍小于配置上限。公差0时返回逐值零偏移，保留均质换号控制。顶球与母球固定，参数进入RackConfig白名单/本机配方与重摆profile，旧版本拒绝。

接触候选邻接范围扩至0.25mm以覆盖微小间隙；实际起始碰撞仍须发生接近且球体已接触，未靠扩大可视球径提前施力。局部压缩过程若短暂无接触力，计算后续闭合间隙的等待时间，在剩余归一化时间内跳至下一接触前，而非立即当作碰撞结束。接触时间尺度依旧近似，非实测材料参数。134项检查及实际Web Mobile回归通过，整体真实感待体验；证据validation/rack-tolerance。
