# 中式八球整体技术实现方案

版本：V1.9 · 2026-10-21。状态：已确认实施基线，分阶段开发。

本方案对应 [产品设计方案](../design/中式八球产品设计方案.pdf) 与 [UI / UX 设计方案](../design/中式八球UIUX设计方案.pdf)。文中的目标能力不代表当前代码已经完成；实施状态见末尾清单。

## 1. 范围与约束

- 使用 Cocos Creator 3.8.7 + TypeScript，保留现有 Main 场景和启动脚本 UUID；新增资源保留各自 `.meta`。
- 面向移动端小游戏，只使用触摸；浏览器用于开发预览。
- 本期为同屏双人、单局对战，预留头像、昵称和连接状态的数据接口。账号、匹配、联网服务器、AI、排名及商业化不在本期。
- 球心在 XZ 平面运动，物理和裁判保持纯 TypeScript，不引入通用物理引擎。视觉的高度和阴影不改变球位。
- 裁判沿用中台协《中式台球竞赛总则（2017 年 1 月修订）》第三章，不增加指袋或普通三次犯规判负变体。现实身体犯规、跳球、飞台及完整赛事不在范围内。
- 核心规则、场景 UUID 和现有测试必须保留。提交前检查公开内容，排除机器绝对路径、私有镜像、内部服务地址、凭据与缓存。

## 2. 已确认体验参数

| 项目 | 实施要求 |
| --- | --- |
| 瞄准 | 台面拖动改变方向，松手保留，触摸取消不出杆 |
| 力度 | 10%–100%，初始 60%，与方向和打点独立 |
| 出杆 | 独立按钮，点击锁定方向、力度、打点、进攻组并启动动画 |
| 触球同步 | 220 ms 触球关键帧同帧提交实际击球且仅一次；调整动画时实际击球随关键帧移动 |
| 动效 | 0–140 ms 后收，140–220 ms 前送，220–480 ms 反馈与图标球离场，480–640 ms 留杆，640–820 ms 复位 |
| 再次出杆 | 动效结束、台面停稳且裁判允许，三项同时满足 |
| 微调 | 以打开时方向为中心 ±5°，拖动连续，两侧点按每次 0.1°，边界钳制 |
| 微调收起 | 松手保留；再次点入口收起；可调力度或打开打点，点击出杆自动收起 |
| 母球打点 | 球杆正面视角，圆内归一化二维偏移；草稿与确认值分离，取消恢复原值 |
| 打点回中 | 每杆停稳并完成裁判结算后自动回中，出杆前保留确认值 |
| 旋转手感 | 简化仿真：高杆跟进，低杆在旋转保留足够时回拉，侧塞主要影响碰库反弹，可组合；效果受力度、距离和碰撞角度影响，中杆不保证定杆 |
| 首版排除 | 弧线球、跳球、抬杆，以及职业赛事级精细物理 |
| 局部放大 | 默认开、可关闭；台面拖动与微调时显示，松手收起但微调展开时保留 |
| 放大内容 | 首次预计接触点、母球接触位置、目标球与辅助线；无目标球时以预计库边为中心，不预测完整加塞轨迹 |
| 放大窗口 | 台面上方一角，避开手指和底部操作，必要时换角；不接收触摸 |
| 默认设置 | 音效开、辅助瞄准开、局部放大开；振动关、减少动态关 |
| 保存与生效 | 设置本机保存，下次沿用；修改立即生效；平台不支持时降级，不阻止对局 |
| 减少动态 | 简化位移，保留 220 ms 触球提示与实际击球同帧同步 |

## 3. 当前实现与差距

基线代码：`BilliardsGame` 负责程序场景、HUD、全局触摸和对局调度；`BilliardsPhysics` 为 240 Hz 平面仿真；`BilliardsRules` 独立裁判；`BilliardsLayout` 为区域分隔计算。

| 领域 | 已有能力 | 缺口与实施方向 |
| --- | --- | --- |
| 场景 | 桌面、六袋、球杆、编号球、半色连续环带 | 按设计统一配色、克制光影和袋口深度；视觉入口与捕获区域共用几何配置 |
| 玩家 | P1/P2 文字、剩余号码、犯规累计 | 资料与座位分离；头像昵称、标准球组图标、长昵称省略与完整身份查看 |
| UI | 顶部/桌面/底部分区 | 专业球房组件、真实安全区、宿主避让、固定触区、状态切换底栏 |
| 输入 | 单指跟踪、摆球、拖动瞄准、力度 | 移除松手击球；独立出杆、微调、打点及弹层手势屏蔽 |
| 出杆 | 同步调用裁判与 strike | 独立时间线、参数快照、触球提交、取消、防重复 |
| 物理 | 平移、碰球、碰库、减速、圆形捕获 | 三轴角速度、滑动/滚动摩擦、跟进回拉、侧塞碰库；更新停稳判定 |
| 裁判 | 开球、选组、自由球、犯规、黑球胜负 | 结构化原因与下一步，替代裁判中的 P1/P2 展示字符串 |
| 辅助 | 球杆方向显示 | 首次接触预测、虚线与母球接触圈、局部放大 |
| 流程 | 即时重开、简单结果文字 | 暂停、重开确认、规则、设置、结算层、查看台面 |
| 平台 | Creator/Web Mobile 开发预览 | 小游戏导出、前后台、安全区、反馈 API、设备性能验证 |

现有力度输入未被完整限制到待击球阶段，顶部重开会立即清局，均须纳入状态权限控制。原浏览器 `unhandledrejection` 根因尚未定位，不能归为已修复。

## 4. 模块职责与迁移

| 模块 | 职责与边界 |
| --- | --- |
| `BilliardsGame` | 保留场景入口，连接模块，逐步缩减；不再集中存放 UI 细节 |
| `GameSession` | 对局权威状态、合法命令、当前玩家、待提交出杆、暂停恢复、重开 |
| `BilliardsPhysics` | 纯 TS 仿真和物理事件，不访问 UI 或平台 |
| `BilliardsRules` | 纯 TS 裁判，输入物理事件，输出结构化结算，不访问玩家头像 |
| `ShotSequence` | 单一出杆时间线和唯一触球事件；表现和实际击球共用进度 |
| 交互控制 | 方向/力度/微调/打点草稿、有效触点、手势归属，不直接修改裁判 |
| `TableView` / `HudView` | 映射球位与界面数据，渲染球桌、身份卡片、底栏和弹层 |
| `AimPredictor` | 纯几何首次接触预测，与真实半径、库边配置一致 |
| 平台适配 | 安全区/宿主占位、前后台、存储、声音、振动与降级 |

优先把配色与设计参数提取为配置，把玩家资料和布局提取为独立纯 TS 模块，再迁移界面组件，避免一次性重写裁判。重复 UI 使用 Cocos 预制体或可复用组件；第一步可先拆成程序构建组件，以减少手工序列化资源带来的兼容风险，再在 Creator 内制作稳定预制体。球桌保留 3D 正交视图。

## 5. 状态与输入

三组状态分别维护：

- 裁判阶段：`placing / ready / shooting / choice / over`，延用规则语义。
- 交互阶段：空闲、瞄准、调力度、微调、打点编辑、出杆准备。
- 覆盖层：无、暂停、设置、规则、重开确认、结算、完整玩家资料。

由对局控制派生 `canAim / canAdjustPower / canEditSpin / canShoot / canPlace`，UI 禁用和输入处理使用同一权限来源。打点弹层不推进仿真，打开时应已处于待击球阶段。暂停和切后台冻结仿真；恢复清掉时间积压，不能追算后台经过的时长。

每次触摸开始时确定归属：弹层 > 按钮 > 力度/微调 > 摆球/瞄准。归属直到结束或取消不变，跨区域不切换手势；只接受一根有效手指。弹层开关、失焦、暂停和重开清理触摸归属。

## 6. 出杆提交与同帧要求

点击时只做预校验，创建不可变快照：`shotId / gameId / player / direction / power / tipOffset / selectedGroup`。不调用 `beginShot`，不改变球速度；直到触球事件才原子提交裁判与物理。

- 时间线跨过触球点时先呈现触球状态，再推进该杆物理，不允许掉帧后直接跳到远离触球的图标状态。
- 使用唯一出杆编号和 `committed` 标志保证最多提交一次。提交前复核球局编号、裁判允许、球已停稳、参数有限值和方向合法；失败则取消，不留半提交裁判状态。
- 触球前暂停、切后台、离开或重开：取消准备，恢复需重新点击。
- 触球后暂停：保留已提交状态，恢复不补打、不回滚。进程被系统销毁后的跨进程恢复另行规划，不能承诺本机永久保存球局。
- 图标复位不恢复母球位置，也不表示可以立即再出杆。
- 音效与已开启振动由实际触球事件触发。减少动态仍使用同一触球事件。

## 7. 打点与旋转模型

面板打点采用相对球杆视角的左右/上下坐标；草稿限制在单位圆，中心吸附与设计 6 像素阈值对应。显示偏移百分比不表示转速。将沿杆坐标转换为桌面方向向量后，映射到初始角速度。

物理状态扩展三轴角速度和必要的静止/滑动/滚动状态；依次加入台呢摩擦、旋转衰减、碰球后的平移与旋转影响、侧塞碰库。不得用 UI 位移或额外固定推力伪装旋转效果。中杆样例先保持基本稳定，再用固定案例校准高低杆和侧塞。

停稳需要考虑仍可能驱动平移的角速度，并采用稳定门槛，不能因某一子步平移速度接近零就结算。单纯残余侧旋的截断策略需与模型一致，避免等待过长。母球摆放、重开和落袋清理对应旋转；裁判结算后只将下一杆打点回中，不清除本杆尚未结束的旋转。

测试案例：近距离正碰高杆跟进、低杆回拉、相同打点远距离衰减、相反侧塞碰同库的方向差异、组合打点、零打点、极限参数稳定性及最长停稳时间。固定参数和球位验证趋势，不在不同几何场景中承诺相同走位。

## 8. 几何、视觉和资源

- 用主题配置统一背景、台呢、库边、木框、文字、强调和错误色；字体与字号按设计角色配置。
- 桌面 UI 参考 393×852，短屏压缩装饰和间距，按钮触区至少 44×44，主要底栏按钮高 48；不把整屏等比例缩小作为唯一适配方式。
- 安全区使用设备真实值，宿主胶囊单独预留。图稿中的时间、电量、系统胶囊不作为游戏 UI 绘制。
- 桌面保持 1:2 台呢比例，六袋完整可见。球杆在母球后方；号码不得超出投影球形。
- 台面半色球连续环带随球旋转，顶部球组使用同配色标准正视图；号码区不可吞没环带。
- 虚线预测母球圆形与目标球扩张半径的首次接触，以及球心可达库边，选择最近有效解；不是零半径射线。局部放大复用同一几何结果。
- 放大窗使用独立裁剪区域，主桌坐标与输入不变。评估局部相机渲染纹理与复用 2D 表现的成本后选择，避免把整个场景再复制一套。
- 图标源为仓库 SVG，按 Cocos 资源兼容情况导出本地图集；需要分部件动画的出杆图标用独立节点或 Graphics 描边，不依赖运行时浏览器 SVG。
- 静态材质与纹理共享，UI 按状态变化更新，避免每帧重建文字和图形；球位与运动中的必要投影持续更新。

## 9. 身份、裁判与反馈

`PlayerProfile` 与规则座位分离，包含稳定 ID、昵称、头像来源和本地/设备视角角色；裁判仍按座位运算。长昵称按宽度省略，点击查看完整资料；空昵称使用“玩家一/玩家二”，头像失败使用同尺寸占位。身份位置固定，只切换回合强调。

裁判输出结构化 `ShotResult`，包含玩家、进袋球、犯规代码、下一位、自由球范围、开球选择和胜负原因。提示文案在表现层生成，所有位置使用同一身份数据。保留事件顺序和现有特殊开球分支。

普通提示 1.5–2 秒退出；需要摆球或选择时持续保留。开球选择纵向排列；结束层支持再开局和查看台面；查看台面不恢复操作。犯规累计移入规则页。

物理事件补充碰撞强度信息供声音使用，裁判不依赖该强度。声音限制高频重叠并复用资源。振动只触球和重要结果，关闭后停止后续反馈。设置使用带版本的本地结构，存储异常回退默认值而不阻断对局。

## 10. 分阶段交付与验收

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 1 主界面与组件 | 主题、玩家资料/卡片、顶部/球桌/底栏布局、真实安全区基础、逐步拆分主脚本 | 现有规则测试通过，Creator 导入无错误，长/短屏无重叠，昵称与半色可辨；早期试跑小游戏导出 |
| 2 击球交互 | 独立出杆、微调、基础辅助线、触球时间线、防重复和取消 | 0 ms 不击球，触球前静止，220 ms 同帧提交一次，触摸取消/暂停不产生幽灵击球 |
| 3 打点旋转 | 面板草稿/确认、偏心回显、旋转模型、结算回中 | 固定案例验证跟进/回拉/侧塞、坐标映射和运动稳定 |
| 4 完整反馈 | 摆球效果、开球面板、结算/查看台面、暂停/规则/设置、放大窗、音效振动 | S01–S15 状态可操作，设置保存与立即生效，前后台正确恢复 |
| 5 小游戏验证 | 微信小游戏构建、开发工具、手机真机与性能 | 实际安全区/宿主区域正确，单指/取消/前后台可用，无未处理异常，资源和性能可接受 |

三类证据分别报告：纯逻辑检查、Creator 实际预览、小游戏真机。浏览器尺寸模拟和类型检查不能替代后两者。性能目标在首批真机基线采集后明确，不能在未测量前宣称已达到帧率。

## 11. 验证与风险

运行 `npm run check`，保留现有 35 项测试；模块迁移后增加有行为意义的状态、时间线和旋转测试。新测试进入 `scripts/test.cjs`，不得只写未运行的测试。

Creator 检查包括资源 UUID、预制体/脚本导入、按钮命中、相机投影和遮罩；小游戏检查包括真实触摸、字体、音频解锁、存储异常、安全区和前后台。新的预览回归需适应独立出杆操作，不能继续依赖旧“松手击球”脚本。

主要风险为旋转手感校准、低帧率触球同步、短屏台面可读性、字体/图集资源体积以及编辑器缓存。分别用固定台面用例、跨关键帧测试、画幅与真机检查、资源统计及 Creator 重新导入验证解决。原 Promise 拒绝问题需取得具体来源和堆栈调查，不吞异常。
