## 共享几何与模块职责

`BilliardsTableGeometry.ts`不依赖Cocos：提供台面及外框、袋口局部坐标、八段库边多边形及内侧轮廓、胶边线段、球心捕获与摆球查询、首次碰撞/落袋预测。`BilliardsPhysics`消费这些边界并输出事件；`BilliardsRules`消费事件而不负责袋型。`BilliardsGame`渲染同一几何轮廓。进袋使用共享的台面开口几何，并额外要求球心与实体胶边的净空至少为球半径。

每袋定义袋喉中点lip、朝袋内的normal、沿开口的tangent和净宽W。角袋沿桌角45°方向，中袋沿长库外法线；中袋与角袋分别构造。圆弧相切连接直库与袋内直边，每个圆弧离散16段；视觉顶面和物理接触轮廓共享离散点，防止入口与碰撞错位。

球球仍为原来的等质量球碰撞。胶边以球心到线段的最近距离与球半径比较，修正重叠，并将原旋转反弹模型应用于接触法线；圆弧袋角产生不同于直库的反弹方向。直库事件保持原左右/上下side语义，裁判基线不变。固定240 Hz及4 m/s上限保持；该离散模型不提供任意大dt或无限速度的连续碰撞保证。

## 进袋与合法摆球

2026-11-05修正支撑与捕获不一致的问题。球心进入共享台面开口多边形，且与实体胶边线段的距离至少为球半径时进袋。`pocketOpeningAt`用于开口包含及接触阴影的支撑查询，`pocketAt`再检查胶边净空。球心仍在台面上或被袋角挡住时继续参与平面运动。

`dropDepth`现在表示开口前缘，角袋为`-J/√2`、中袋为`-J`，J为袋角圆弧半径。视觉后沿的深度以独立的`backDepthInBallRadii`保存。首次边界预测在前缘检查`pocketAt`，连续碰撞和子步捕获复用同一查询。进袋只发出一次事件，并清平移和角速度。

原实现要求球心越过袋内一个半径的代理线，在已经挖空的区域保留了隐形支撑，导致低速球悬停。此次将球心失去支撑与实际开口对齐。这里仍为平面捕获代理，真实垂直落袋、弹袋与球之间的三维支撑需要后续模型。

摆球查询要求球心位于台面允许范围、整球不穿胶边、未落入代理捕获区，再检查其他球与线后条件。自动回位兼容API也复用此查询；游戏仍显式关闭自动回位。

XZ平面没有真实重力下落、袋口皮革变形、吐球或精细支承面积。代理面只解决当前模型“何时移除球”的问题，不能用于声称真实袋台手感已校准。

## 辅助线与渲染

首次接触预测将母球半径加入胶边线段（线段主体加圆形端点），同时检查能容纳整球的落袋代理面；不再把袋口挡成整段矩形库边。球球首次接触仍按原扩张半径射线计算，选择最近结果。不预测完整加塞轨迹。

渲染采用正确外框和台面比例；袋口黑区为袋喉、弧形转入及袋内后沿组成的多边形，不再用半径85 mm的六个圆柱。胶边按共享轮廓生成顶面；相机留出完整2.82×1.54 m外框，号码随新视口继续投影。头线及置球点由未变的长边尺寸保持原值；宽度坐标和合法范围统一从共享参数取得。

## 回归与验收

覆盖六袋低速/满力直进、袋前不提前捕获、擦袋角弹开、偏移超出净空拒绝、普通碰库、白球落袋与裁判、袋角非法摆球、辅助线与真实首次事件一致，以及可见轮廓不超出台框。旧测试若把球放在台面边缘就要求立即进袋，需要迁移到真实代理面并补充“不提前进袋”的反例，不能保留大圆以迎合旧用例。

类型/Node、Creator构建、浏览器DOM触摸、手机体验和微信平台结果分别记录。本轮不运行微信开发者工具。未经本轮复测的历史运行报告不作新袋口验收证明。

## 2026-11-06 进袋下落表现

原先捕获事件直接隐藏球节点，视觉上出现瞬间消失。现由独立 PocketAnimation 保存捕获位置，在约320ms内保持原球体尺寸、向袋内移动并加速下沉，沿移动方向滚动；下沉到袋底以下后才隐藏节点。台呢、胶边和袋底通过现有深度测试遮挡球体。接触阴影随失去台面支承结束。

下落使用与游戏相同的固定时间步。暂停/后台冻结下落，重开清空全部下落状态，多球各自保存进度。最后一颗球下落完成后才结算当前杆，避免落白回位、开球进8重置和结果弹窗截断动画。“减少动态”保留必要的空间下落反馈。

320ms与6m/s²为视觉调校参数，XZ捕获事件仍由共享袋口几何产生。袋内水平运动使用有界向内插值，未模拟完整三维袋壁碰撞、皮网和袋内多球碰撞。当前属于捕获后的表现层代理。

278项Node检查通过。Creator 3.8.8 Web Mobile构建完成，六袋×慢速/高速的72项组件驱动浏览器检查通过，检查完整球体下沉、暂停、减少动态和结算时序。原生Main预览已重启并观察到开始界面，专项下落检查在Web Mobile执行；真机/微信沿用豁免。详细记录见 validation/pocket-support/fall-animation.json。
