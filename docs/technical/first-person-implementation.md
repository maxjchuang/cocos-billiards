## 首版实施配置

新增ViewState、AimGesture、CameraMath、CameraRig、ViewGeometry、TableView、BallTexture、BallView与TrajectoryView，Game统一接入生命周期。受光材质通过resources/materials/first-person.mtl显式打包builtin-standard，异步加载完成后才开放运行。

相机后距0.45m，候选0.40/0.35m；眼高默认0.20、范围0.15–0.25m；前看0.38m；垂直FOV55°、near0.01、far6。安全求解同时检查眼位、母球与实际杆头/杆体视线；水平中低杆被库边挡住时退俯视，不能自动抬杆。36个位置×2高度包含24个正确回退。

淡切280ms（140ms切投影）；阈值6逻辑像素、主轴比1.3、横向每场景宽60°、纵向每场景高0.20m限幅。存储eight-club.view.v1独立白名单；结果/规则强制状态优先于暂停保留。锁机位在220ms唯一提交前建立，图标820ms结束后仍保持到停稳。

LDR方向光0.85、环境0.8；PCF3、1024 shadow map、固定覆盖1.65m、bias0.0001/normalBias0.0002。HDR路径未单独验收。球径与球心不变，台面接触影Y=0.00015、路径Y=0.00045m。白虚线0.022/0.018m，金虚线0.030/0.018m，宽0.0025m。节点和网格复用，预测构建不因观察高度/切换重跑。密集球阵（球间1mm内邻接≥8对）等待瞄准稳定550ms再启动完整预测，稀疏台面仍70ms；输入变更立即清旧结果。此调度避免连续重新求解昂贵接触网，但单个物理步不可抢占，原始最大帧耗时仍公开记录。

证据见[验收目录](../../validation/first-person/README.md)。新增238项Node检查中的59项覆盖第一人称；浏览器、原生与性能范围分别记录，用户视觉评审不由自动断言替代。未改物理、裁判、AI规划或220ms提交模块。

## 1. 范围与关键结论

使用Cocos Creator 3.8.7与现有TypeScript工程。主相机增加透视模式，HUD继续正交；沿用同一份对局、240Hz物理、裁判、AI、ShotSequence与预测数据。第一人称只是人类瞄准/出杆后的观察方式，不增加抬杆物理、跳球、弧线球、自由环绕、追球、陀螺仪或双指依赖。AI首版仍俯视。

本轮不能只把相机转下来，也不能把设计SVG直接当3D资源使用。必须完成：相机/状态与输入隔离，低视角模型，固定场景光照与贴台面阴影，正确深度遮挡，生命周期与回归。

**当前球心高度本身没有发现错误**：Cloth盒体厚0.02m，中心Y=-0.01m，实际顶面Y=0；球节点Y=`TABLE.radius=0.028575m`，正好满足相切。V1.15.1图稿里的台面高度是绘图坐标，不应复制成运行时0.002m高度。修复真实感靠正确几何、材质和投影，不能把球下沉、压扁或改半径。

| `BilliardsTrajectoryView.ts` | 同一ShotPrediction与相机 → 深度正确的路线/终点与可见性状态 | 不改预测状态/点集，不把截断绘图终点当停点 |

### 3.1 视角偏好与运行态

- `preferredMode: overhead | first-person`：设备共享、本机保存，首次默认overhead。建议存储键`eight-club.view.v1`，数据带version与白名单；损坏/未知值回俯视，写入失败提示本局有效。原五项设置和AI难度键不迁移。
- `effectiveMode`：当前展示模式。强制俯视或运动中临时返回不写preferredMode。
- `forcedReason`：placing / group-choice / break-choice / ai / result / unsafe-camera等可诊断原因。
- `transition`：源/目标、进度、generation；`shotPoseLock`：gameId、shotId、相机position/rotation/projection等展示快照。
- 观察高度保存为会话参数，首版不新增长期高度偏好；暂停恢复保留，新局初始化。减少动态直接到最终安全机位。
- 重开、切换玩法、销毁、进入后台使旧transition generation失效，不能在旧动画结束后覆盖新局的视角。

## 4. 相机、坐标与状态机

### 4.1 一台世界相机，HUD相机保持独立

保留当前背景清屏相机和UI相机，世界相机在ORTHO与PERSPECTIVE之间切换，避免两台3D相机长期重复渲染。`layoutHud`只产出playArea/安全区，CameraRig应用rect、宽高比、投影与位姿，然后统一更新矩阵。

坐标约定：米制，XZ为台面运动平面，+Y向上。`clothTopY=0`取自实际Cloth顶面；球心`clothTopY+R`，R=0.028575m。渲染层必须统一这个基准。贴地路线、接触阴影的微小深度偏置仅用于抗Z冲突，不能移动球或改变落袋判断。

候选第一人称机位：母球C与水平单位方向d，眼位`(C.x-d.x*distance, clothTopY+eyeHeight, C.z-d.z*distance)`；目标沿d前方、lookAt使用+Y为up，不能沿用俯视的-Z up。目标距离/俯仰与高度共同满足母球位于场景下方约2/3–4/5处。微调只改变d，竖向观察只改变eyeHeight/构图。

以下均为原型候选：后距0.35–0.55m，高0.15–0.25m，**垂直**FOV50–60°；近裁剪面先在0.005–0.02m范围试验，远面只覆盖本地球桌场景，避免继承不必要的30m深度范围。近面和光照偏置须一起检查杆头裁断、Z冲突与深度精度；未经试景不冻结。

### 4.2 状态优先级

从高到低：销毁/无球局 → 规则强制俯视 → 后台/旋转阻塞/暂停 → 出杆准备/运动快照 → 用户正常瞄准请求。视角入口权限与场景触摸权限来自同一状态结果，不能只把按钮变灰而保留输入。

| 事件/阶段 | 相机处理 | 输入及偏好 |
|---|---|---|
| placing/未选组/choice/AI/over | 俯视 | 不覆盖偏好；禁止第一人称瞄准 |
| 人类ready且mayShoot | 安全求解后按偏好显示 | 可切换；手势与底部控件独立 |
| 切换开始 | 保存目标与generation，安全淡切 | 清理当前拖动/微调展开，保留方向；锁场景拖动与出杆 |
| 切换中暂停/后台/改尺寸 | 终止未完成动画，保持合法状态 | 不自动出杆；恢复重新计算最终安全机位 |
| 点击出杆 | 先确认相机已稳定，保存相机快照，再走原ShotSequence.begin | 0–220ms禁止切换/拖动；参数与机位冻结 |
| 220ms触球 | 只由原ShotSequence/commitShot推进 | 图标、球启动与音效同帧；相机不调用提交 |
| shooting且原为第一人称 | 固定出杆机位，不跟随移动母球 | 允许回俯视，禁止反向进入第一人称；临时返回不写偏好 |
| 动效820ms结束、球尚未停 | 继续保存运动机位 | 相机快照不能随ShotSequence.snapshot清空而丢失 |
| 停稳+裁判结算 | 处理强制状态或进入下一杆机位 | 只有合法人类ready才恢复偏好 |
| 触球前暂停/触球后暂停 | 遵守既有取消/冻结规则；分别保存待恢复视角 | 人类不自动重击；AI仍用既有锁杆恢复机制且俯视 |
| reset/new-game/destroy | 失效旧相机快照、过渡和手势 | 不重用上局shotId；偏好独立保存 |

实现时必须区分`shotSequence.active`与`committed`：220–820ms图标仍活动，但运动阶段应允许第一人称回俯视，不能沿用active就全部禁用的判断。

从俯视切透视不直接线性插值投影矩阵。首版优先对playArea做240–320ms候选短淡切，在遮罩最高阶段切投影并应用安全端点；HUD保持稳定。若之后加入空间移动，需要验证整个路径而不是只验证首尾。减少动态不播放位移/淡切，但保留220ms触球。

### 4.3 相机安全求解

相机可在球桌外，不使用`validTablePlacement`把眼位强行钳到台面内。相机安全依据实际低视角模型的视觉体积；物理库边线段不能代表桌框厚度或杆体。

1. 从当前方向、实际打点与力度生成的杆头位置构造默认机位；检查眼位、近裁剪面与可见杆段是否进入桌框/胶边。平面球/水平杆的顶高低于最小眼位及near余量，不增加跳球体积。
2. 检查母球中心、杆头与可见接触区域的视线及屏幕位置。其它球造成的正常遮挡不通过移球或透明化解决。
3. 依设计顺序尝试安全缩短后距、提高视点；候选数有界，使用确定性次序，不循环搜索。
4. 无安全解则退回俯视并短提示。保持ShotRequest与偏好不变，不提高FOV、藏库边或下沉球来掩盖穿模。
5. 安全机位保持，尺寸/方向发生实质变化才重算；近阈值有滞回，避免抖动。运动阶段用锁定机位，不追球重新求解。

初始障碍代理用共享轮廓挤出得到的棱柱/AABB及杆/球包围体，必要时对实际网格射线复核。无需通用物理引擎。允许通过低视角失败fixture修正视觉代理的精度，但不能改现有击球碰撞参数。

## 5. 触摸与出杆整合

HUD优先命中，再判断场景区域；视角按钮只属于HUD。触点进入第一人称场景时记录touchId、逻辑起点、当前yaw与观察参数，**不调用pointAt**。基于`hudPixelRatio`转换逻辑坐标，不能使用设备DPR硬除，兼容缩放的Creator嵌入预览。

候选主轴判定：累计位移≥6px，且某轴绝对值≥另一轴1.3倍时锁定。本次手势只输出该轴；未达主轴优势不改变状态。越阈值首帧先重设增量锚点，避免突然补上全部死区位移。水平角度候选每个playArea宽约60°，以playArea而非整屏宽归一化；竖向按有效场景高归一化映射候选观察范围。

水平角采用连续累积并归一化为sin/cos方向；微调的现有±5°/0.1°逻辑保留。切换或垂直手势禁止重新计算并覆盖direction，避免微小浮点漂移。抬手保留结果，下一触点只是新的增量锚点。第二指、取消、移出场景、暂停与后台均结束手势而不出杆。

在`shoot()`入口加“不是transitioning”条件；相机锁定和ShotSequence.begin组成同一次合法操作。物理快照不增加FOV/相机位置，展示快照另存，以gameId/shotId关联。不能用另一个setTimeout在220ms提交；既有时序继续是唯一真相。

## 6. 低视角模型、号码和贴地真实感

### 6.1 模型与坐标

- 从`CUSHION_PATHS.polygon/nose`生成闭合侧面与顶面，从实际render顶面取高度。当前0.038m只是已有显示高度，不包装为厂家实测。
- 木框现有平面mesh的Y缩放不会生成厚度，必须显式挤出侧面。接口接收统一的clothTopY，禁止不同组件各写一个0或0.002。
- 袋口视觉沿用`POCKETS.outline`，补暗部内壁与必要的台面缺口；不能让完整实心Cloth盒体透过洞口。可见开口/遮挡必须与现有代理对应；不能把outline直接当新的落袋捕获区域。
- 保留pocketed事件的权威时刻；首版继续既有隐藏行为，不额外引入3D下落、吐球或皮口形变规则。
- 杆头/轴线与实际打点一致；近视角显示现有锥形杆网格的真实透视，不能改成HUD竖线。贴库后段冲突先由相机安全与正确遮挡解决，不能擅自增加抬杆物理或移动杆头接触点。当前水平杆模型在部分贴库中低杆姿态会被库边遮挡，按设计退回俯视；不会自动改成高杆或抬高杆尾伪装通过。

### 6.2 光照与阴影的实施选择

先在M0做真实Cocos试景比较，而不是继续把示意图当效果证明。建议第一人称球体使用引擎受光材质、平滑法线、固定世界光向和低强度环境光；保留现有全色/半色颜色与连续环带。光源不能作为相机子节点，否则转镜头时阴影会跟着玩家跑。

优先验证单个固定方向光的有限范围阴影贴图，候选512/1024尺寸、仅必要物体投射，并检查阴影偏置造成的“球离地”或表面斑点。质量与性能都过门槛后冻结配置。可补轻量的**世界空间接触阴影**：中心由球在台面上的落点给出，接触核心紧、外缘柔；固定光向决定偏移，不使用屏幕圆。贴地网格启用深度测试、透明混合、关闭深度写入，并裁到有效台呢范围，不跨进袋洞或穿上库面。

不能以强黑色AO脏斑、过大的柔影或把球往下压来“修复”悬浮感。高光较小、暗部连续，半色环带与号牌不能断裂。阴影投射不对物理施力，也不影响随机球阵。

俯视暂保留V1.14的程序材质与HUD明暗；第一人称禁用`drawBallLighting`和台面号码HUD，避免双重高光/双号码。共享球节点与网格，按模式切材质/展示层，不维护第二套球的位置。若未来统一两视角受光材质，须单独做俯视外观回归。

### 6.3 号码的首选实现

第一人称优先采用球面UV号码：在连续环带/球色纹理上生成两侧白底号码区，随现有视觉四元数滚动；球面和号码自然受深度遮挡。数字图集在开发期程序生成并本地打包，不依赖运行时DOM Canvas、远程字体或第三方美术。

号码滚到背面时允许不可见；HUD目标球号与玩家剩余球图仍提供身份信息。不能为了“永远能看见数字”画穿透前球的HUD号牌。若UV失真需要替代，必须另行证明替代标识位于球体表面、限于轮廓内并受深度遮挡，不能跳过FP-A07。

## 7. 轨迹与投影

`ShotPrediction`继续只产出XZ点集、pocket与状态；切换视角和竖向观察不改变trajectoryKey、不取随机数、不额外试算。水平瞄准、力度和打点改变仍走现有失效策略。

第一人称路线使用场景网格/折线带，Y=`clothTopY+epsilon`，实际深度测试开启、深度写入关闭，绘制顺序与球/库深度缓冲一致。白/金颜色、双虚线及圆十字/菱形/进袋箭头语义保持。接触球用半透明世界球面或轮廓表达，不能把屏幕圆当球面截面。

几何层按稳定的世界弧长产生虚线，允许为近远可读性调整显示采样，但不裁掉后续预测数据。点集裁剪与投影遵守相机前方/near/far边界；屏幕线宽只负责可读性，不能强制放大远处的终点体积。共面epsilon从小值试验，既无闪烁，也不能看成悬于球心高度。

新增独立展示状态`inView/partiallyOffscreen/occluded`，不覆盖`running/complete/incomplete/invalid`。屏外完整预测只提示“全轨迹见俯视”，不把屏边绘制点标作最终停点；回俯视仍能读取原完整结果。部分被遮挡的路线按深度隐藏；“是否可见”的UI提示可以保守，但不能透视显示它。

母球大小不再用`worldToScreen(x+R).x - centre.x`统一估计，旋转到其它方位时该值可能接近0。第一人称的球、号牌、首碰轮廓和终点均使用真实世界几何与相机深度；仅HUD图例固定逻辑像素。

局部放大仅在effectiveMode=overhead时显示，保持原开关值与六袋避让策略。切换前清除旧世界/俯视绘图，禁止一帧同时显示两套路线。

## 8. 每帧顺序、资源与性能

建议Game单帧顺序：处理已排队合法输入 → 按原顺序推进ShotSequence/固定步物理/裁判 → 同步球与杆节点 → 根据最终阶段更新ViewState与CameraRig → 应用viewport并刷新相机矩阵 → 绘制模式对应的轨迹/号码/阴影 → HUD。逻辑触球仍由原链触发，不能因相机先后调整而延后一帧实际击球或声音。

暂停/后台不积累相机过渡时间或新的物理时间；恢复显式继续。viewport改变重新应用投影和最终安全机位，丢弃旧触点；旋转提示仍阻断输入。按钮锁定覆盖ShotSequence和camera transition两个条件。

- 资源一次构建、对象池复用，不每帧创建材质/纹理/Label。数值姿态可逐帧更新，几何仅在预测/配置变化时更新。
- 路线显示缓存与预测缓存分开：纯视角变化只更新投影/材质参数，不重跑240Hz仿真。
- 第一人称不同时画放大窗；俯视不启用额外灯光阴影成本。所有临时网格、材质、监听在destroy释放。
- 继承本机393×852/DPR2/60FPS上限：正常瞄准平均≥50FPS，持续拖动/过渡测试≥45FPS，P95≤33.4ms；与相同配置V1.14对照。每场景预热1秒后采样10秒、3轮全量保留；50次切换后稳定节点/材质数、无持续增长。
- V1.14历史参考为普通约59.38FPS、放大约60FPS、挑战AI约59.44FPS；只是同机历史基线，不能当第一人称实测或手机认证。

若阴影成本超标，优先缩小阴影覆盖范围/分辨率并限制投射者，保留接触核心与正确遮挡。不能用关闭深度测试、取消阴影或放大球的方式通过性能门槛。

## 9. 验收与发布约束

完整矩阵见计划。纯数学/状态测试与Creator实际材质检查分开；同杆等价的纯TS比较要求逐值一致，真实帧循环的最终位置容差≤1mm且首碰、进袋列表、胜负/犯规一致。

FP-A11是发布门槛：低/高视点、近/远球、贴库与关辅助线的截图/短录屏均需呈现球底贴台、阴影连续，不得用图稿通过替代引擎试景。自动检测只能证明高度和投影数据正确，真实感仍需检查引擎画面并记录评审结果。

保留默认俯视与可关闭新视角入口的开发开关，便于同种子A/B；禁用时读取到first-person偏好也安全回俯视且不覆盖存储。未通过发布矩阵前不开启正式入口。撤回只涉及展示层，不能回滚已验收物理/裁判/AI。

真实手机与微信构建/工具/真机仍按用户既有授权豁免。材料与平台兼容边界据实记录；无未完成第一人称验证的“全部通过”表述。
